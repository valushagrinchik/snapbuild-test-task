# SnapBuild — тестовое задание Fullstack Developer

Решение тестового задания по развитию продуктового лендинга [Снэпбилд](https://snapbuild.ru/): сохранение существующих секций, добавление пяти новых и публикация на GitHub Pages.

## 1. Краткое описание выполненной работы

Лендинг реализован как статический сайт (`HTML/CSS/JS`). Проект основан на исходных ассетах snapbuild.ru: сохранены исходные секции, исправлена структура `<head>`, вынесены инлайн-скрипты и стили в отдельные файлы, удалены дублирующиеся ассеты. В страницу логично встроены пять новых секций, выполненных в визуальном языке оригинала. Сборка направлена в папку `docs/` для публикации на GitHub Pages.

## 3. Инструкция по локальному запуску

```bash
# Локальный сервер
npm run dev

# Сборка в docs/ для GitHub Pages
npm run build

# Проверить собранную версию
npm run start
```

После `npm run dev` открыть: `http://localhost:8080`.

## 4. Использованный стек

- **HTML5** — семантическая разметка
- **CSS3** — стили, адаптивная сетка, анимации
- **Vanilla JavaScript** — интерактивность без зависимостей
- **GitHub Pages** — статический хостинг
- **npm-скрипты** — локальный сервер и копирование сборки

## 5. Перечень пяти добавленных секций

1. **Тарифы** (`#pricing`) — три тарифных плана, интерактивный выбор с выделением выбранного и строкой статуса.
2. **Примеры материалов** (`#materials`) — сетка форматов контента, который можно создавать в Снэпбилд.
3. **Отзывы** (`#testimonials`) — три карточки с цитатами клиентов, должностями и компаниями.
4. **Форма обратной связи** (`#contact`) — поля заявки с клиентской валидацией и сообщением об успешной отправке.
5. **Интеграции** (`#integrations`) — площадки и сервисы, с которыми работает платформа.

## 6. Как анализировалась стилистика исходного сайта

Анализ вёлся по скачанным CSS-файлам оригинального лендинга:

- **Цвета**: серый фон `#F2F2F4`, белые карточки, акцентный градиент `#ff6d3c → #ff6ba7 → #bb6dff`, чёрный `#000` текст и CTA.
- **Типографика**: Satoshi/Inter, крупные заголовки с `letter-spacing: -0.03em`, плавная `clamp()`-типографика.
- **Формы**: `border-radius: 24px` у карточек, `100px/12px` у кнопок, мягкие тени и отступы на `vw`/`clamp`.
- **Ритм**: центрированный контейнер ~1200px, одинаковые вертикальные ритмы и `section`-отступы.

## 8. Что не удалось реализовать и почему

- **Динамическая CMS**: исходник использует кастомную CMS, оставшиеся `data-cms-*` атрибуты — наследие разметки, не подключённые к бэкенду.
- **Реальная отправка формы**: без серверной части/Formspree форма показывает только UI-успех.
- **Полная очистка разметки**: часть инлайн-стилей и `data-cms-*` атрибутов осталась из-за объёма, т.к. их массовое удаление требует дополнительной ручной проверки, чтобы не сломать CSS-селекторы.
